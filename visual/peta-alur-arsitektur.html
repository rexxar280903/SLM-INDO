Bagian 2 · FineWeb-2 ind_Latn · contoh teks buatan, angka audit nyata

Seperti apa data yang nanti masuk ke model?

Pretraining memakai teks biasa: model belajar menebak token berikutnya. Di bawah ada empat contoh dokumen dan perubahan formatnya. Seluruh teks, metadata, dan ID token adalah ilustrasi buatan; belum berasal dari korpus proyek.

01 · Korpus bersih: JSONL, satu dokumen per baris

{"id":"contoh-001","source":"web-contoh","lang":"id","split":"train","text":"Petani menanam padi saat musim hujan."}
{"id":"contoh-002","source":"artikel-contoh","lang":"id","split":"train","text":"Perpustakaan desa membuka kelas membaca setiap Sabtu."}
{"id":"contoh-003","source":"web-contoh","lang":"id","split":"validation","text":"Panel surya mengubah energi cahaya menjadi listrik."}
{"id":"contoh-004","source":"artikel-contoh","lang":"id","split":"test","text":"Pasar tradisional mulai ramai sejak pagi."}

Field text ditokenisasi. Field id/source/lang/split membantu audit dan pemisahan dokumen; metadata tidak menjadi input model. Split ditetapkan (D35): val = 1% dokumen berdasarkan hash teks, sehingga duplikat exact selalu masuk split yang sama; test = split test resmi FineWeb-2.

Sumber: notes/audit-fineweb2.md dan uji 8 row group (8.000 dokumen). Ini pengamatan sampel, bukan statistik korpus. Contoh yang terbuang hampir semuanya halaman judi ("slot gacor", "togel"). "Bandar" tidak dihitung karena ada "Bandar Lampung" dan "bandar udara".

Dekontaminasi: dua kriteria

  • Benchmark (FLORES 997 + 1.012 kalimat, SmSA 12.760 teks, 1.000 artikel Wikipedia): dokumen dibuang bila ada ≥1 n-gram 13 kata yang sama. Item 8–12 kata dicocokkan utuh.
  • Test web (36.821 dokumen test resmi): dibuang bila ≥50% n-gram dokumen ada di test (near-duplicate).
  • Mengapa bukan "≥1 n-gram" untuk test web? Aturan itu membuang 13,7% dokumen hanya karena template situs yang sama (median overlap 6,8%). Kriteria baru membuang ±0,1%.

Tokenizer: SentencePiece BPE 16.384

  • 214 token, kelipatan 128 (ramah TPU). ID khusus: unk 0, bos 1, eos 2.
  • Byte fallback: karakter langka → token byte, sehingga tidak ada token "tidak dikenal".
  • Normalisasi identity, tanpa dummy prefix → decode(encode(teks)) = teks persis.
  • Uji sampel kecil: round-trip 73/73 dokumen, 4,38 byte/token, fertility 1,61 token/kata. Nilai final menunggu sampel 1 GB.

ID di atas adalah contoh, kecuali EOS=2 yang memang ID asli tokenizer kita. Tokenizer nyata dapat memecah kata menjadi beberapa subword. Dengan vocab 16.384, ID muat dalam uint16 (2 byte/token). meta.json menyimpan sha256 tokenizer dan setiap shard, jumlah token, byte, dan dokumen.

input_ids = [81, 207, 913, 44, 305, 126, 9]

Target bergeser satu token: setelah “Petani” model menebak “menanam”; setelah titik model menebak EOS. Saat training, contoh panjang dipotong/di-pack sesuai konteks S10–S125. Label padding diabaikan; gunakan causal mask agar model tidak melihat token masa depan. Contoh ini hanya sepanjang 7 posisi.

Dekontaminasi: jangan sampai model sudah membaca soal ujian

Tetapkan set evaluasi→Normalisasi untuk pencocokan→Exact match + n-gram / near-duplicate→Karantina dokumen cocok→Kelompokkan duplikat & split→Latih tokenizer hanya pada train

Deduplikasi menghapus pengulangan di korpus. Dekontaminasi memeriksa apakah korpus memuat isi benchmark atau set uji yang disisihkan. Dokumen yang cocok dikeluarkan dari pretraining dan data pelatihan tokenizer; ambang pencocokan dan jumlah yang dibuang dicatat.

Bagian 3

Apa yang terjadi dalam satu run training

Sama untuk semua model dan skala; yang berbeda hanya konfigurasi arsitektur dan ukuran. Langkah 4–7 diulang ribuan kali.

1 · Rencana (plan_run)Skala, arsitektur, seed. Budget FLOPs = FLOPs/token B0 × token referensi → jumlah langkah arsitektur ini
2 · InisialisasiBobot acak dari seed, N(0; 0,02), proyeksi keluar /√(2L). AdamW β (0,9; 0,95), wd 0,1
3 · Data loaderJendela 2.049 token dari train.bin. Urutan = f(seed, langkah), sama untuk semua arsitektur. Batch dibagi ke 8 chip
4 · Forward ↻Token → embedding → 8/10/14/12 blok (remat per blok) → logit 16.384 per potongan 8.192 token → cross-entropy
5 · Backward ↻jax.value_and_grad per micro-batch (lax.scan), rata-rata, clip norm 1,0. bf16, inti GDN fp32
6 · Update ↻AdamW. LR = f(progres FLOPs): warmup 3% (≥50 langkah) → cosine ke 10%
7 · Log ↻Loss, norma gradien, LR, token/detik, MFU tiap 10 langkah. bpb val di 10%, 20%, … budget. Checkpoint tiap 30 menit
8 · SelesaiBudget FLOPs habis (atau token pada kontrol token-matched) → evaluasi akhir → simpan checkpoint final + ringkasan hasil ke runs/

Varian N2: di titik alih tertentu (10%, 25%, atau 50% dari langkah referensi), sebagian layer dialihkan ke full attention. L4/L8/L12 adalah contoh untuk S125; penempatan S25 mengikuti konfigurasi run. Lihat bagian 6.

Hyperparameter dan budget per skala

SkalaBatch × konteksToken/langkahMicro × akumulasiBudget FLOPsLangkah B0WarmupLR awal

Sama untuk semua run

  • AdamW β1 0,9 · β2 0,95 · ε 1e-8
  • Weight decay 0,1 hanya pada matriks proyeksi; embedding, norm, conv, A_log, dt_bias tanpa decay
  • Clip norma gradien 1,0 · tanpa dropout · bf16 + master fp32
  • Compute-matched: langkah = ⌊budget ÷ FLOPs per langkah⌋. Kontrol token-matched = langkah B0
  • Seed 0 = penyaringan; seed 1–3 = konfirmasi
  • Sweep LR: {0,5; 1; 2}× untuk B0 & B2 di S10 dan S25 → LR dikunci

Jadwal LR terhadap progres FLOPs

Sumbu x = fraksi budget FLOPs, bukan nomor langkah. Karena itu jadwal N2 tetap benar walau biaya per langkah berubah setelah konversi.

Attention di L4, L8, L12 mengikuti aturan D28; posisi alternatif diuji lewat ablation. Secara analitik, KV-cache 4× lebih kecil karena 3 dari 12 layer menyimpan KV, lalu GQA H/2 memangkas 2× lagi (total 8×). Total memori juga mencakup state rekuren (1,77 MB fp32) dan buffer konvolusi (0,12 MB).

Isi setiap blok (pre-norm)

x→RMSNorm→Mixer→+ x→RMSNorm→FFN SwiGLU→+
  • Mixer = Gated DeltaNet (9 layer) atau full attention (3 layer)
  • FFN SwiGLU: 768 → 2.048 (dua cabang) → 768, sama di semua blok, tanpa bias
  • Sambungan residual (+ x) menjaga aliran gradien

Gated DeltaNet: memori tetap ("buku catatan")

x→proyeksi q, k, v→conv pendek→gerbang α (lupa), β (tulis)→update state S→o = S·q→gate + norm
St = αt · St−1 · (I − βt kt kt⊤) + βt vt kt⊤
  • 12 head × state 64 × 64 per layer (fp32) → ukuran tetap, tidak tumbuh dengan panjang teks
  • Conv kausal kernel 4 + SiLU pada q, k, v; L2-norm q, k; β = σ(x·Wb); g = −eA·softplus(x·Wa + dt_bias)
  • α memudarkan ingatan lama; β menimpa ingatan untuk kunci yang sama (aturan delta)
  • Training memakai bentuk chunkwise (perkalian matriks per potongan) → cocok untuk TPU

Full attention + GQA: ingatan tajam

x→Q (12 head)K, V (6 head)→RoPE θ=10.000→softmax(QKᵀ/√64)·V→proyeksi O
  • Melihat semua token sebelumnya secara langsung → recall kuat
  • GQA H/2: 2 head query berbagi 1 pasang key/value → KV-cache 2× lebih kecil (iso-cache: anggaran yang sama dengan MLA dan CLA di grid, D27)
  • Di TPU memakai Pallas flash attention (matriks T×T tidak disimpan); fallback XLA

Dibekukan (D27): layer attention dipasangkan berurutan, layer pertama = sumber (MHA), layer kedua = penerima tanpa WK/WV. Dengan jumlah attention genap, cache = ½ MHA. Jika ganjil (h3 di S25/S125), cache = ⅔ dan dilaporkan apa adanya. h6-cla di S10/S25 identik dengan MHA, jadi tidak dijalankan.

Bagian 5a · src/slm/gdn.py · diuji: chunkwise = rekuren

Bagaimana Gated DeltaNet dilatih cepat di TPU: bentuk chunkwise

Bentuk rekuren memperbarui memori S token demi token. Hasilnya benar tetapi berurutan (2.048 langkah), sehingga lambat di TPU. Bentuk chunkwise memotong urutan menjadi 32 chunk × 64 token. Di dalam chunk, semua operasi berupa perkalian matriks; di antara chunk, hanya S yang diteruskan.

2.048 token → 32 chunk × 64 token

S₀ chunk 1→chunk 1→S₁→chunk 2→…→S₃₂(lax.scan, 32 langkah)

① Di dalam chunk

A = β ⊙ (KKᵀ) ⊙ D, segitiga bawah ketat

Drj = exp(γr − γj) ≤ 1 adalah peluruhan kumulatif α antara token j dan r.

② Triangular solve

U = (I + A)⁻¹ [βV − βΓ K S₀]

Aturan delta untuk 64 token sekaligus. Alternatif gdn_solver=product hanya memakai perkalian matriks.

③ Output & state baru

O = Γ Q S₀ + (QKᵀ ⊙ D) U
S₆₄ = ΓC S₀ + (ΓC/Γ · K)ᵀ U

Bukti kebenaran: tests/test_gdn.py membandingkan output, state akhir, dan gradien dengan bentuk rekuren untuk panjang 37–128 dan chunk 16–64 (11 kasus lulus). Di TPU, matmul fp32 "default" memakai pass bf16, sehingga inti GDN dipaksa float32; galat dan biayanya diukur oleh tpu_check.py.

Kontrol: hybrid akhir yang sama, dilatih sejak langkah pertama (titik alih 0%). H4 menargetkan penghematan compute 10–20% menuju bpb yang sama; ini hipotesis, bukan hasil. Novelty N2 masih perlu diperiksa terhadap W1.

Bobot acak→Linear penuh→Titik alih→Transfer proyeksi kompatibel→Hybrid akhir→Ukur FLOPs menuju bpb target
  • Pada contoh S125, layer L4/L8/L12 dialihkan; layer lain tetap linear. N2 juga diuji pada S25 dengan penempatan layer yang ditentukan dalam konfigurasi.
  • Titik alih 10% / 25% / 50% mengacu ke jumlah langkah referensi, bukan persentase FLOPs. Contoh ilustratif 10.000 langkah: alih di 1.000 / 2.500 / 5.000.
