Bentuk data · contoh buatan

Seperti apa data yang nanti masuk ke model?

Pretraining memakai teks biasa: model belajar menebak token berikutnya. Di bawah ada empat contoh dokumen dan perubahan formatnya. Seluruh teks, metadata, dan ID token adalah ilustrasi buatan; belum berasal dari korpus proyek.

01 · Korpus bersih: JSONL, satu dokumen per baris

{"id":"contoh-001","source":"web-contoh","lang":"id","split":"train","text":"Petani menanam padi saat musim hujan."}
{"id":"contoh-002","source":"artikel-contoh","lang":"id","split":"train","text":"Perpustakaan desa membuka kelas membaca setiap Sabtu."}
{"id":"contoh-003","source":"web-contoh","lang":"id","split":"validation","text":"Panel surya mengubah energi cahaya menjadi listrik."}
{"id":"contoh-004","source":"artikel-contoh","lang":"id","split":"test","text":"Pasar tradisional mulai ramai sejak pagi."}

Field text ditokenisasi. Field id/source/lang/split membantu audit dan pemisahan dokumen; metadata tidak otomatis menjadi input model. Persentase split belum ditetapkan. Satu kelompok dokumen duplikat harus berada pada split yang sama.

02 · Tokenisasi → shard biner

Petanimenanampadisaatmusimhujan.EOS
token_ids = [81, 207, 913, 44, 305, 126, 9, 2]
dtype     = uint16
berkas    = train-00000.bin

ID di atas adalah contoh, termasuk EOS=2. Tokenizer SentencePiece nyata dapat memecah kata menjadi beberapa subword. Dengan vocab 16k, ID muat dalam uint16 (2 byte/token). Simpan manifest berisi versi tokenizer, jumlah token, checksum, dan batas dokumen.

03 · Pasangan input dan target

input_ids = [81, 207, 913, 44, 305, 126, 9]
labels    = [207, 913, 44, 305, 126, 9, 2]
shape     = [batch_size, sequence_length]

Target bergeser satu token: setelah “Petani” model menebak “menanam”; setelah titik model menebak EOS. Saat training, contoh panjang dipotong/di-pack sesuai konteks S10–S125. Label padding diabaikan; gunakan causal mask agar model tidak melihat token masa depan. Contoh ini hanya sepanjang 7 posisi.

Dekontaminasi: jangan sampai model sudah membaca soal ujian

Tetapkan set evaluasi→Normalisasi untuk pencocokan→Exact match + n-gram / near-duplicate→Karantina dokumen cocok→Kelompokkan duplikat & split→Latih tokenizer hanya pada train

Deduplikasi menghapus pengulangan di korpus. Dekontaminasi memeriksa apakah korpus memuat isi benchmark atau set uji yang disisihkan. Dokumen yang cocok dikeluarkan dari pretraining dan data pelatihan tokenizer; ambang pencocokan dan jumlah yang dibuang dicatat.

teks_uji   = "Panel surya mengubah energi cahaya menjadi listrik."
korpus_web = "Panel surya mengubah energi cahaya menjadi listrik."
keputusan  = "karantina dari pretraining: exact match"

Contoh cocok ini buatan. Kemiripan sebagian diperiksa dengan n-gram/near-duplicate; ambang perlu ditetapkan dan diaudit agar tidak terlalu banyak membuang teks yang hanya memiliki frasa umum.

FLORES-200 · teks evaluasi bahasa

Benchmark terjemahan multibahasa. Riset ini memakai sisi Indonesia ind_Latn sebagai teks untuk mengukur bpb, tanpa mengharuskan model menerjemahkan. Bekukan versi dan split yang dipakai; jangan masukkan teksnya ke korpus pretraining.

{"id":"flores-ilustrasi-01","lang":"ind_Latn",
 "text":"Kereta tiba di stasiun pada sore hari."}

Kalimat buatan, bukan kutipan FLORES. Sumber benchmark FLORES-200.

SmSA · klasifikasi sentimen

Tugas IndoNLU dengan label positive, negative, neutral. Setelah pretraining, tambahkan head klasifikasi, fine-tune pada train resmi, pilih pengaturan lewat validasi, dan ukur macro-F1 pada test.

Pelayanannya ramah dan cepat.	positive
Barang datang dalam keadaan rusak.	negative
Toko buka pukul sembilan pagi.	neutral

Contoh buatan, format TSV: teks [tab] label. Jaga semua split SmSA terpisah dari pretraining; train SmSA hanya boleh dipakai pada tahap fine-tuning. Definisi dan format SmSA.

Bagian 3

Apa yang terjadi dalam satu run training

Sama untuk semua model dan skala; yang berbeda hanya konfigurasi arsitektur dan ukuran. Langkah 4–7 diulang ribuan kali.

1 · KonfigurasiSkala (S10–S125), jenis layer, rasio, varian KV, seed, budget token
2 · InisialisasiBobot acak (dari nol), optimizer AdamW, jadwal LR warmup + cosine
3 · Data loaderBaca shard uint16 → potong sesuai konteks skala (1024–2048 token) → batch dibagi ke 8 chip
4 · Forward ↻Token → embedding → blok sesuai skala (8/10/14/12) → logit 16k → loss cross-entropy (tebak token berikutnya)
5 · Backward ↻Gradien dihitung otomatis (jax.grad), presisi bf16, clip gradien 1,0
6 · Update ↻AdamW memperbarui bobot; LR mengikuti jadwal
7 · Log ↻Loss, bpb, token/detik tiap N langkah; eval val tiap M langkah; checkpoint tiap 30–60 menit
8 · SelesaiBudget FLOPs habis (atau token pada kontrol token-matched) → evaluasi akhir → simpan checkpoint final + ringkasan hasil ke runs/

Varian N2: di titik alih tertentu (10%, 25%, atau 50% dari langkah referensi), sebagian layer dialihkan ke full attention. L4/L8/L12 adalah contoh untuk S125; penempatan S25 mengikuti konfigurasi run. Lihat bagian 6.

Contoh penempatan attention di L4, L8, L12; posisi tetap diuji melalui ablation. Secara analitik, KV-cache 4× lebih kecil karena 3 dari 12 layer menyimpan KV, lalu GQA memangkas 3× lagi. Total memori juga mencakup state rekuren dan buffer konvolusi.

Isi setiap blok (pre-norm)

x→RMSNorm→Mixer→+ x→RMSNorm→FFN SwiGLU→+
  • Mixer = Gated DeltaNet (9 layer) atau full attention (3 layer)
  • FFN SwiGLU: 768 → 2048 → 768, sama di semua blok
  • Sambungan residual (+ x) menjaga aliran gradien

Gated DeltaNet: memori tetap ("buku catatan")

x→proyeksi q, k, v→conv pendek→gerbang α (lupa), β (tulis)→update state S→o = S·q→gate + norm
St = αt · St−1 · (I − βt kt kt⊤) + βt vt kt⊤
  • 12 head × state 64 × 64 per layer → ukuran tetap, tidak tumbuh dengan panjang teks
  • α memudarkan ingatan lama; β menimpa ingatan untuk kunci yang sama (aturan delta)
  • Training memakai bentuk chunkwise (perkalian matriks per potongan) → cocok untuk TPU

Full attention + GQA: ingatan tajam

x→Q (12 head)K, V (4 head)→RoPE→softmax(QKᵀ/√d)·V→proyeksi O
  • Melihat semua token sebelumnya secara langsung → recall kuat
  • GQA: 3 head query berbagi 1 pasang key/value → KV-cache 3× lebih kecil
  • Varian lain yang diuji di grid: MHA, MLA, CLA

Bagian 6

Metode N2: linear-first warm-start

Ide yang diuji: mulai dari bobot acak dengan semua layer Gated DeltaNet, kemudian ubah sebagian layer menjadi full attention. Jika biaya per langkah fase linear lebih rendah, N2 berpotensi menghemat compute menuju kualitas target. Penghematan belum terbukti.

Fase 1 · 0% → titik alih

12 layer linear: biaya perlu diukur

alih di
10% / 25% / 50%
→
Fase 2 · titik alih → selesai

Hybrid 3:1: L4, L8, L12 jadi attention

Kontrol: hybrid akhir yang sama, dilatih sejak langkah pertama (titik alih 0%). H4 menargetkan penghematan compute 10–20% menuju bpb yang sama; ini hipotesis, bukan hasil. Novelty N2 masih perlu diperiksa terhadap W1.

Bobot acak→Linear penuh→Titik alih→Transfer proyeksi kompatibel→Hybrid akhir→Ukur FLOPs menuju bpb target
  • Pada contoh S125, layer L4/L8/L12 dialihkan; layer lain tetap linear. N2 juga diuji pada S25 dengan penempatan layer yang ditentukan dalam konfigurasi.
  • Titik alih 10% / 25% / 50% mengacu ke jumlah langkah referensi, bukan persentase FLOPs. Contoh ilustratif 10.000 langkah: alih di 1.000 / 2.500 / 5.000.
  • Q/K/V/O hanya dapat dipakai ulang langsung jika bentuk tensor cocok. Konversi ke GQA atau MLA memerlukan aturan pemetaan tersendiri; bobot baru dan momen optimizer harus ditangani secara eksplisit.
  • Bandingkan seed, data, optimizer, konteks, arsitektur akhir, serta kualitas target yang sama. Catat biaya konversi dan run yang tidak mencapai target.

FLOPs total = FLOPs fase linear + FLOPs konversi + FLOPs fase hybrid

KV-cache analitik · konteks 512 token

Batch 1; cache bf16/fp16, 2 byte per nilai; MB desimal. Panjang 512 sesuai batas terkecil pembanding (Goldfish). Bobot, state rekuren, dan buffer konvolusi tidak masuk batang KV.

2 × layer attention × head KV × 64 × 512 × 2 / 10⁶ MB

B2: KV=0, tetapi state tetap ada. Untuk rancangan 12 head × 64 × 64, state B2 ≈1,18 MB (bf16) atau 2,36 MB (fp32). B3: ≈0,88 / 1,77 MB. Buffer konvolusi ditambahkan terpisah.

Jumlah parameter · acuan S125

E1–E3 dihitung dari konfigurasi GPT-2 (termasuk posisi, bias, LayerNorm, dan embedding tied). B0/B1 memakai rumus rancangan tanpa bias. B2/B3 menunggu implementasi mixer.

Satuan: juta parameter. Hasil analitik dibulatkan.

Angka B0/B1 mengasumsikan d=768, 12 layer, SwiGLU 2048, vocab 16k, dan RMSNorm. Parameter tiap arsitektur harus dihitung ulang sebelum menyamakan budget eksperimen.
